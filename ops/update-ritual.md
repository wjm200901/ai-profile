# 更新仪式

> 档案不是写出来的，是**维护出来的**。没有仪式的档案，三个月后就是有害的遗迹。

## 每周：15 分钟（周五下午）

| 时间 | 动作 | 产出 |
|---|---|---|
| 5 分钟 | 扫本周日志/聊天，找"改变了看法"的瞬间 | 1–3 条候选 |
| 5 分钟 | 用 [`prompts/weekly-review.md`](../prompts/weekly-review.md) 让 AI 输出变更建议 | diff 清单 |
| 5 分钟 | 只改"立刻改"的条目，更新 `as_of` | 提交 |

**小技巧**：把这件事放进日历，命名为"更新档案"，不要叫"整理资料"——后者永远会被推迟。

## 每月：45 分钟（月末）

1. 复盘：这个月在回避什么问题？
2. 检查：哪一节的 `confidence` 该下调？
3. 删减：如果只能留一节，删掉哪节？删掉的就是水分。
4. 补证据：`identity/02-capabilities.md` 有没有新证据？`memory/projects/` 要不要加卡？
5. 更新 `ops/changelog.md` 的月度条目。

## 每季：2 小时

1. 重读 `identity/00-core.md`——一句话还成立吗？
2. 重读 `identity/04-principles.md`——有没有一条你已经不信了？
3. 检查 `privacy/layers.md` 清单——有没有新的敏感信息？
4. 更新版本号（`profile.json` 的 `version`），打 git tag：`v0.2.0`。
5. 问一个残酷问题：**如果陌生人只读这份档案，他会高估我还是低估我？**

## 什么时候必须立刻更新

- 换工作 / 开始新项目
- 改变了对某个重要问题的看法
- 档案里的事实被外部事件推翻
- 有人指出你的档案"不像你"

## 版本号规则

| 变更 | 版本 |
|---|---|
| 修正错字、格式 | patch（0.1.1） |
| 新增文件、补充内容 | minor（0.2.0） |
| 改变一句话定位、核心结构 | major（1.0.0） |

## 提交信息

```
docs(core): 更新当前在做项目
docs(principles): 新增第 6 条"承认沉没成本"
chore: 每周复盘 2026-11-06
```
